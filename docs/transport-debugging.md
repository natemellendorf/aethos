# Transport: Local Peer-to-Peer Debugging Guide

Quick reference for understanding and troubleshooting the FileDropLink transport layer.

## Directory Layout

Each peer has this structure under its home directory:

```
peer/
  identity/             # Curve25519 key pair
  store/
    aethos.sqlite       # Chunks, outbox, inbox tables
  transport/
    inbox/              # Inbound frames (deposited by external courier)
    outbox/             # Outbound frames (generated by `pump`)
    archive/            # Processed inbox files (terminal — do not re-forward)
    parts/
      chunk-<hex>/      # Temporary chunk part files during multi-part assembly
      manifests/        # Cached manifest canonical bytes (for reassembly)
    send-cursors.json   # Per-chunk cursor tracking which part to send next
```

## File Prefix Convention

| Prefix | Meaning | Where it appears |
|--------|---------|-----------------|
| `out-` | Generated by `send()` during pump | outbox/ |
| `in-`  | Renamed from `out-` when archived after processing | archive/ |
| `*.bad` | Malformed or unreadable frame | archive/ |
| `reassembled-<manifestId>.bin` | Fully reassembled payload | archive/ |

## Happy-Path Flow (A sends file to B)

```
1. aethos send --home A    # Chunks file, enqueues manifest+envelope in outbox table
2. aethos pump --home A    # Writes out-*.bin frames to A/outbox/
3. [courier]               # Moves A/outbox/* -> B/inbox/
4. aethos ingest --home B  # Reads B/inbox/, stores chunks, caches manifest, checks reassembly
5. (repeat 2-4 until all chunk parts delivered)
6. ingest detects all chunks present -> writes reassembled-<id>.bin to B/archive/
```

## What to Expect During a Successful Transfer

**After `send`:**
- A's outbox table has manifest + envelope (status=queued)
- A's chunks table has all chunks

**During pump/ingest rounds:**
- A/outbox/ fills with `out-*.bin` each round (cleared by courier)
- B/inbox/ fills from courier (cleared by ingest)
- B/archive/ fills with `in-*.bin` (processed frames)
- B/parts/chunk-*/ accumulates part files until each chunk is complete
- B/parts/manifests/ has `<manifestId>.bin` after first manifest frame arrives

**After delivery:**
- B/archive/reassembled-<manifestId>.bin exists
- B/parts/chunk-*/ directories cleaned up (deleted after assembly)
- `aethos transfers --home B --json` shows `"state": "complete"`

## Using `transfers` for Programmatic Detection

```bash
# Human-readable
aethos transfers --home ./peerB

# Machine-readable JSON
aethos transfers --home ./peerB --json
```

JSON output:
```json
{
  "transfers": [{
    "manifestId": "abc123...",
    "direction": "receiving",
    "state": "complete",
    "totalBytes": 204800,
    "chunksTotal": 7,
    "chunksAvailable": 7,
    "reassembledFile": "/path/to/reassembled-abc123.bin"
  }]
}
```

States: `queued` | `sending` | `delivered` | `receiving` | `reassembling` | `complete`

## Troubleshooting Checklist

**B/outbox/ is empty but archive/ has `out-*.bin` files growing each round:**
- The courier's `forward_archive` is picking up already-processed files.
  After the `archiveGood` fix, processed files use `in-` prefix and won't match `out-*.bin` globs.
  Verify your courier only globs `out-*.bin` from archive (or doesn't forward archive at all).

**Chunks never assemble (part directories keep growing but never get cleaned up):**
- Each `ingest` invocation scans the chunk directory on disk. If parts span multiple invocations,
  they'll be found on the next invocation that receives the final part.
- Check: do the part files match the expected count? `ls parts/chunk-<hex>/` and look for
  `part-N-of-M.bin`. If you have M files, assembly should trigger.

**`transfers --json` shows `chunksAvailable < chunksTotal` and it's stuck:**
- The pump may not be sending all chunks. Check that the planning budget is large enough
  for all chunks to appear in the plan. The pump uses an inflated planning budget (10x the
  actual send budget) to ensure all chunks are included.

**Reassembled file never appears even though all chunks are available:**
- Reassembly happens during `ingest`, not `pump`. Make sure `ingest` runs after
  the final chunk part is received.
- Check that `parts/manifests/<id>.bin` exists — without the cached manifest,
  reassembly can't determine which chunks to combine.
